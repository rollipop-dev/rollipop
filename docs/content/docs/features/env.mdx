---
title: Environment Variables
---

Rollipop loads `.env` files and replaces `import.meta.env.*` accesses during bundling. Use full property names; dynamic lookups and destructuring are not supported.

```ts
if (import.meta.env.MODE === 'development') {
  // code inside here will be tree-shaken in production builds
  console.log('Development Mode');
}
```

## Built-in Constants

- `import.meta.env.MODE` (`'development' | 'production'`): The [mode](/docs/get-started/configuration#mode) the app is running in.
- `import.meta.env.BASE_URL` (`string | undefined`): The base URL the app is being served from, when supplied by the development server.

## Environment Files

Rollipop loads environment variables from the following files in your project root:

```
.env                # Loaded in all cases
.env.local          # Loaded in all cases, should be ignored by git
.env.[mode]         # Only loaded in specified mode
.env.[mode].local   # Only loaded in specified mode, should be ignored by git
```

### Priority Order

Environment variables are loaded and merged in the following order, with later files taking precedence:

1. `.env`
2. `.env.local`
3. `.env.[mode]` (e.g., `.env.development`, `.env.production`)
4. `.env.[mode].local`

Shell and CI environment variables take precedence over file values, including empty strings.

Only keys declared in the loaded environment files are exposed. To override a value from your shell or CI, declare the key in an environment file first.

Variable references are expanded after all files are merged, so derived values use the final overrides. Loading environment files does not modify `process.env`.

## Variable Prefix

Only variables prefixed with `ROLLIPOP_` are exposed by default:

```bash title=".env"
ROLLIPOP_API_URL=https://api.example.com
ROLLIPOP_FEATURE_FLAG=true
SECRET_KEY=abc123  # This will NOT be exposed
```

```ts title="App.tsx"
console.log(import.meta.env.ROLLIPOP_API_URL); // https://api.example.com
console.log(import.meta.env.ROLLIPOP_FEATURE_FLAG === 'true'); // true
```

Values are strings. Exposed values are embedded in the client bundle and must not contain secrets.

## Variable Expansion

Reference other variables with `${NAME}` (`dotenv-expand` syntax):

```bash title=".env"
ROLLIPOP_API_BASE=https://api.example.com
ROLLIPOP_API_URL=${ROLLIPOP_API_BASE}/v1
ROLLIPOP_API_FULL_URL=${ROLLIPOP_API_URL}/users
```

## Configuration

Set the directory with [`envDir`](/docs/get-started/configuration#envdir) and the prefix with [`envPrefix`](/docs/get-started/configuration#envprefix):

```ts title="rollipop.config.ts"
import { defineConfig } from 'rollipop';

export default defineConfig({
  envDir: './config', // Load .env files from ./config directory
  envPrefix: 'MY_APP_', // Only expose variables with MY_APP_ prefix
});
```

### Custom File Basename

Set [`envFile`](/docs/get-started/configuration#envfile) to change the basename:

```ts title="rollipop.config.ts"
import { defineConfig } from 'rollipop';

export default defineConfig({
  envFile: '.rollipop-env',
});
```

This loads `.rollipop-env`, `.rollipop-env.local`, `.rollipop-env.[mode]`, and `.rollipop-env.[mode].local` from `envDir`. Use a file name, not a path.

## Mode-Specific Variables

`rollipop start` uses `development`; `rollipop bundle` uses `production`. Override with [`mode`](/docs/get-started/configuration#mode). The CLI's `--dev` flag does not change environment file selection or `import.meta.env.MODE`.

```bash title=".env.development"
ROLLIPOP_API_URL=https://dev-api.example.com
ROLLIPOP_DEBUG=true
```

```bash title=".env.production"
ROLLIPOP_API_URL=https://api.example.com
ROLLIPOP_DEBUG=false
```
