title: Reporter
---

Reporters receive build events, HMR failures, transform progress, and client logs.

## Reporter Interface

To create a custom reporter, implement the `Reporter` interface:

```ts
interface Reporter {
  update(event: ReportableEvent): void;
}
```

`ReportableEvent` includes every event published in the current Rollipop process. Standalone builds publish build events, while a dev server also publishes HMR, client, and server events.

When an event comes from a dev-server bundler instance, it includes `bundlerId`, which identifies the bundler that produced the event.

## Event Types

### Build Events

#### `bundle_build_started`

Emitted when a bundle build starts.

```ts
{
  type: 'bundle_build_started';
  bundlerId?: string;
}
```

#### `bundle_build_done`

Emitted when a bundle build completes successfully.

```ts
{
  type: 'bundle_build_done';
  bundlerId?: string;
  totalModules: number;
  transformedModules: number;
  cacheHitModules: number;
  duration: number;
  bundleFilePath?: string;
}
```

#### `bundle_build_failed`

Emitted when a bundle build fails with an error. HMR update failures are reported as `hmr_failed` instead.

```ts
{
  type: 'bundle_build_failed';
  bundlerId?: string;
  error: Error;
}
```

### Diagnostic Events

| Event         | Fields                                                                      | Description                                                                      |
| ------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `build_log`   | `level: 'debug' \| 'info'`, `log: BuildDiagnosticLog`, `bundlerId?: string` | Captured Rolldown plugin logs.                                                   |
| `build_error` | `level: 'warn' \| 'error'`, `log: BuildDiagnosticLog`, `bundlerId?: string` | Captured bundler diagnostics. Build and HMR failures also have their own events. |

`BuildDiagnosticLog` contains `message` and optional `code`, `plugin`, `stack`, `id`, `hook`, `frame`, `loc` (`file`, `line`, `column`), and `meta`.

### HMR Events

#### `hmr_updates`

Emitted when HMR updates are ready to send to connected clients.

```ts
{
  type: 'hmr_updates';
  bundlerId: string;
  updates: BindingClientHmrUpdate[];
  changedFiles: string[];
}
```

#### `hmr_failed`

Emitted when an HMR update fails with an error.

```ts
{
  type: 'hmr_failed';
  bundlerId?: string;
  error: Error;
}
```

### Transform Events

#### `transform`

Emitted during module transformation, providing progress information.

```ts
{
  type: 'transform';
  bundlerId?: string;
  id: string; // Module ID being transformed
  totalModules: number | undefined; // Total number of modules
  transformedModules: number; // Number of modules processed for progress
}
```

### Watch Events

#### `watch_change`

Emitted when a file change is detected in watch mode.

```ts
{
  type: 'watch_change';
  bundlerId?: string;
  id: string; // Path of the changed file
}
```

### Client Log Events

#### `client_log`

Emitted when the client application logs to the console. This is compatible with Metro's client log format.

```ts
{
  type: 'client_log';
  bundlerId?: string;
  level: 'trace' | 'info' | 'warn' | 'log' | 'group' | 'groupCollapsed' | 'groupEnd' | 'debug' | 'error';
  data: any[];  // Arguments passed to console method
}
```

### Dev Server Events

| Event                                     | Fields                                        |
| ----------------------------------------- | --------------------------------------------- |
| `client_connected`, `client_disconnected` | `client: WebSocketClient`                     |
| `client_message`                          | `client: WebSocketClient`, `data: ws.RawData` |
| `client_error`                            | `client: WebSocketClient`, `error: Error`     |
| `server_ready`                            | `host: string`, `port: number`                |
| `cache_reset`                             | No additional fields.                         |

`server_ready` marks completion of server setup, before the HTTP listener starts. `cache_reset` is emitted by MCP and dashboard reset actions.

The CLI filters `client_log` events out of configured reporters unless `--client-logs` is enabled. MCP app-log capture is independent of this flag.

## Custom Reporter Example

Handle the events your integration needs:

```ts title="my-reporter.ts"
import type { Reporter, ReportableEvent } from 'rollipop';

export class BuildReporter implements Reporter {
  update(event: ReportableEvent): void {
    switch (event.type) {
      case 'bundle_build_done':
        console.log(`Built ${event.transformedModules} modules in ${event.duration}ms`);
        break;
      case 'bundle_build_failed':
      case 'hmr_failed':
        console.error(event.error);
        break;
    }
  }
}
```

Use your custom reporter in the config:

```ts title="rollipop.config.ts"
import { defineConfig } from 'rollipop';
import { BuildReporter } from './my-reporter';

export default defineConfig({
  reporter: new BuildReporter(),
});
```
