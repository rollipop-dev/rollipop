## Client Types

Add `rollipop/client` to `compilerOptions.types` in your existing `tsconfig.json`:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "types": ["rollipop/client"]
  }
}
```

Keep any existing `types` entries. This registers types for `import.meta.env`, `import.meta.glob`, and `import.meta.hot`.

Alternatively, add a triple-slash reference to a declaration file included by your `tsconfig.json`:

```ts title="rollipop-env.d.ts"
/// <reference types="rollipop/client" />
```

## Environment Variables

Declare your environment variables in `ImportMetaEnv`. `MODE` and `BASE_URL` are already typed:

```ts title="rollipop-env.d.ts"
interface ImportMetaEnv {
  readonly ROLLIPOP_API_URL: string;
  readonly ROLLIPOP_FEATURE_FLAG: string;
}
```

Include this file in `tsconfig.json` and keep it free of top-level `import` or `export` statements. Environment file values are strings; declarations do not validate their presence at build time.

See [Environment Variables](/docs/features/env) for file loading, prefixes, and precedence.

## Glob Imports

Pass a generic for the module namespace or selected export:

```ts
const files = import.meta.glob<{ default: string }>('./messages/*.ts');
// Record<string, () => Promise<{ default: string }>>

const eagerFiles = import.meta.glob<string>('./messages/*.ts', {
  import: 'default',
  eager: true,
});
// Record<string, string>
```

Without a generic, ordinary glob imports return `unknown`; known query strings such as `?raw` and `?url` infer `string`. Query handling still requires a matching plugin. The generic does not validate matching files' exports.

See [Glob Import](/docs/features/glob-import) for patterns and options.

## Type Checking

Rollipop transforms `.ts` and `.tsx` files without a plugin. Run type checking separately:

```bash
yarn tsc --noEmit
```

The [`tsconfig`](/docs/get-started/configuration#tsconfig) option selects the configuration used during bundling.
