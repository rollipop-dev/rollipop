title: Configuration
---

Rollipop loads `rollipop.config.ts` from the project root. Other JS and TS extensions are also supported.

## `defineConfig`

`defineConfig` provides configuration types and accepts an object or a function.

### Static Configuration

```ts title="rollipop.config.ts"
import { defineConfig } from 'rollipop';

export default defineConfig({
  // ...
});
```

### Dynamic Configuration

Use a function to configure by command or extend defaults:

```ts title="rollipop.config.ts"
import { defineConfig } from 'rollipop';

export default defineConfig((context) => {
  return {
    ...context.defaultConfig,
    mode: context.command === 'bundle' ? 'production' : 'development',
  };
});
```

**DefineConfigContext:**

| Property        | Type                  | Description                                                                                                  |
| --------------- | --------------------- | ------------------------------------------------------------------------------------------------------------ |
| `command`       | `string \| undefined` | The current CLI command being executed (e.g., `'start'`, `'bundle'`). May be `undefined` if not run via CLI. |
| `defaultConfig` | `DefaultConfig`       | The default configuration object provided by Rollipop. Useful for extending defaults.                        |

The function can also be async:

```ts title="rollipop.config.ts"
import { defineConfig } from 'rollipop';

export default defineConfig(async (context) => {
  const customPlugins = await loadPlugins();

  return {
    ...context.defaultConfig,
    plugins: customPlugins,
  };
});
```

## Configuration Merging

`resolve.sourceExtensions`, `resolve.assetExtensions`, `prelude`, `polyfills`, and `plugins` append to defaults with duplicates removed. An empty array does not clear them. A plugin's `config` hook can mutate the merged arrays to remove entries.

Reporters are combined. `rolldownOptions` overrides are composed in merge order.

Rollipop also accepts Rolldown input options such as `external`, `moduleTypes`, `optimization`, and `tsconfig`. Use `output` for output options. Rollipop manages the entry, platform, plugins, logging, and output format.

## root

- **Type:** `string`
- **Default:** `process.cwd()`

Project root directory, used for module resolution and resolving the app entry. Options that accept paths may have their own resolution rules; use absolute paths when referring to files outside the project root.

## mode

- **Type:** `'development' | 'production'`
- **Default:** `'development'` for `rollipop start`, `'production'` for `rollipop bundle`.

Controls environment file selection, `import.meta.env.MODE`, and transform defaults. `--dev` controls bundle development flags independently; it does not change `mode` or select a different `.env` file.

```ts
export default defineConfig({
  mode: 'production',
});
```

## entry

- **Type:** `string`
- **Default:** `'index.js'`

The entry point file for your application.

```ts
export default defineConfig({
  entry: 'index.js',
});
```

## resolve

Module resolution configuration.

<Callout>
  `resolve` extends Rolldown's `InputOptions['resolve']`, replacing `extensions` with
  `sourceExtensions` and `assetExtensions`, and adding the options below.
</Callout>

### resolve.sourceExtensions

- **Type:** `string[]`
- **Default:** `['ts', 'tsx', 'js', 'jsx', 'mjs', 'cjs', 'json']`

File extensions to resolve as source files.

### resolve.assetExtensions

- **Type:** `string[]`
- **Default:** images (`bmp`, `gif`, `jpg`, `jpeg`, `png`, `psd`, `svg`, `webp`, `xml`), video (`m4v`, `mov`, `mp4`, `mpeg`, `mpg`, `webm`), audio (`aac`, `aiff`, `caf`, `m4a`, `mp3`, `wav`), documents (`html`, `pdf`, `yaml`, `yml`), fonts (`otf`, `ttf`), and archives (`zip`).

File extensions to resolve as asset files.

### resolve.alias

- **Type:** `Record<string, string | string[] | false> | Array<{ find: string | RegExp; replacement: string }>`

Substitute one package or module path for another in `import` or `require` statements.

Object values accept a replacement string, an ordered list of replacements, or `false` to ignore a module:

```ts title="rollipop.config.ts"
import path from 'node:path';
import { defineConfig } from 'rollipop';

export default defineConfig({
  resolve: {
    alias: {
      '@': path.resolve('src'),
      '@components': path.resolve('src/components'),
    },
  },
});
```

Array aliases preserve declaration order and support `RegExp` find patterns:

```ts title="rollipop.config.ts"
import path from 'node:path';
import { defineConfig } from 'rollipop';

export default defineConfig({
  resolve: {
    alias: [
      { find: '@', replacement: path.resolve('src') },
      { find: /^@features\/(.+)/, replacement: path.resolve('src/features/$1') },
    ],
  },
});
```

The first matching array entry is applied first. When `find` is a regular expression, `replacement` can use replacement groups such as `$1`.

Use array aliases when replacements need to be resolved by other plugins' `resolveId` hooks.

Use absolute paths for file-system aliases; relative replacements are used as-is.

### resolve.mainFields

- **Type:** `string[]`
- **Default:** `['react-native', 'browser', 'main']`

Fields to check in package.json when resolving packages.

### resolve.aliasFields

- **Type:** `string[][]`
- **Default:** `[['react-native'], ['browser']]`

Package fields containing per-module path aliases.

### resolve.conditionNames

- **Type:** `string[]`
- **Default:** `['react-native']`

Condition names for exports field resolution in package.json. `import` or `require` is added automatically according to the importing module.

### resolve.preferNativePlatform

- **Type:** `boolean`
- **Default:** `true`

If `true`, Rollipop will resolve platform-specific files with `.native` suffix.

For example:

- **true**: `index.android.js` → `index.native.js` → `index.js`
- **false**: `index.android.js` → `index.js`

### resolve.symlinks

- **Type:** `boolean`
- **Default:** `true`

Whether to resolve symlinks to their symlinked location.

### Other Resolver Options

| Option                   | Type                       | Default            | Description                                                                      |
| ------------------------ | -------------------------- | ------------------ | -------------------------------------------------------------------------------- |
| `resolve.extensionAlias` | `Record<string, string[]>` | —                  | Resolve an explicit extension to alternatives, e.g. `{ '.js': ['.ts', '.js'] }`. |
| `resolve.exportsFields`  | `string[][]`               | `[['exports']]`    | Package export-map fields.                                                       |
| `resolve.mainFiles`      | `string[]`                 | `['index']`        | File names tried for directory imports.                                          |
| `resolve.modules`        | `string[]`                 | `['node_modules']` | Module search directories.                                                       |

`resolve.tsconfigFilename` is deprecated; use top-level [`tsconfig`](#tsconfig).

## transform

Source code transformation configuration.

<Callout>
  `transform` option extends Rolldown's `InputOptions['transform']` with Rollipop-specific transform
  extensions.
</Callout>

### transform.jsx

- **Type:** `false | 'react' | 'react-jsx' | 'preserve' | JsxOptions`
- **Default:** automatic runtime, with development output controlled by the bundle's `dev` flag

`'react'` selects the classic runtime, `'react-jsx'` selects the automatic runtime, `'preserve'` leaves JSX intact, and `false` rejects JSX.

```ts title="rollipop.config.ts"
import { defineConfig } from 'rollipop';

export default defineConfig({
  transform: {
    jsx: {
      runtime: 'automatic',
      importSource: 'react',
      compiler: {},
    },
  },
});
```

`compiler` enables [React Compiler](/docs/features/react-compiler). `refresh.include` and `refresh.exclude` select Fast Refresh files; see [Dev Server](/docs/features/dev-server#fast-refresh).

### transform.define

- **Type:** `Record<string, string>`

Replace expressions during bundling. Values are JavaScript source strings:

```ts
export default defineConfig({
  transform: {
    define: { __APP_VERSION__: JSON.stringify('1.0.0') },
  },
});
```

Rollipop already defines `__DEV__`, `process.env.NODE_ENV`, `process.env.DEBUG_ROLLIPOP`, and exposed [`import.meta.env` values](/docs/features/env).

### transform.flow

- **Type:** `RollipopReactNativeFlowConfig`

Flow parsing options.

`transform.flow.requireDirective`

- **Type:** `boolean`
- **Default:** `false`

When `true`, only files containing an `@flow` or `@noflow` directive comment are parsed as Flow. By default, every JavaScript module is parsed as Flow.

```ts
export default defineConfig({
  transform: {
    flow: {
      requireDirective: true,
    },
  },
});
```

### transform.babel

Custom Babel transformation rules.

`babel.rules`

- **Type:** `TransformRule<babel.InputOptions>[]`

Define custom Babel transformation rules for specific files.

```ts
export default defineConfig({
  transform: {
    babel: {
      rules: [
        {
          filter: { id: /\.custom\.js$/ },
          options: {
            plugins: ['custom-babel-plugin'],
          },
        },
      ],
    },
  },
});
```

**BabelTransformRule:**

```ts
interface BabelTransformRule {
  filter?: HookFilter | TopLevelFilterExpression[];
  options: babel.InputOptions | ((code: string, id: string) => babel.InputOptions);
  standalone?: boolean;
}
```

With `standalone: false` (the default), options from matching rules are merged, and Babel parses and transforms each matching module once.

With `standalone: true`, rules run separately, in declaration order, before the merged rules. Code-based filters and options callbacks receive the output of preceding transforms.

<Callout type="warn">

Each standalone Babel rule adds a separate parse and transform pass. Use a narrow `filter` to limit the cost.

</Callout>

### transform.swc

SWC options and custom transformation rules.

`swc.native`

- **Type:** `RollipopReactNativeSwcConfig`

Configure built-in SWC transforms:

| Option            | Type                                                                            | Default                   | Description                                               |
| ----------------- | ------------------------------------------------------------------------------- | ------------------------- | --------------------------------------------------------- |
| `plugins`         | `[string, Record<string, unknown>, { filter?: TopLevelFilterExpression[] }?][]` | —                         | WASM path, plugin config, and optional per-plugin filter. |
| `runPluginFirst`  | `boolean`                                                                       | `false`                   | Run WASM plugins before type stripping.                   |
| `externalHelpers` | `boolean`                                                                       | `true`                    | Import helpers from `@swc/helpers`.                       |
| `jest`            | `boolean`                                                                       | `false`                   | Enable Jest hoisting.                                     |
| `react`           | `RollipopReactNativeReactConfig`                                                | —                         | JSX and React Compiler options.                           |
| `module`          | `{ type?: 'unambiguous' \| 'commonjs' }`                                        | `{ type: 'unambiguous' }` | Preserve modules or convert them to CommonJS.             |
| `globals`         | `Record<string, string>`                                                        | —                         | Replace expressions.                                      |

Each WASM plugin filter matches the original source and applies only to that plugin.

`react` accepts `runtime` (`'Preserve'`, `'Automatic'`, or `'Classic'`), `importSource`, `pragma`, `pragmaFrag`, `throwIfNamespace`, `development`, and `compiler`. `runtime` defaults to `'Preserve'`. Explicit `native.react.compiler` fields override `transform.jsx.compiler`, including replacement of filter arrays.

`native.runPluginFirst` controls whether WASM plugins run before (`true`) or after (`false`, the default) TypeScript/Flow types are removed.

```ts
import { createRequire } from 'node:module';
import { defineConfig } from 'rollipop';

const require = createRequire(import.meta.url);

export default defineConfig({
  transform: {
    swc: {
      native: {
        plugins: [[require.resolve('@swc/plugin-remove-console'), {}]],
        runPluginFirst: true,
      },
    },
  },
});
```

`swc.rules`

- **Type:** `TransformRule<swc.Options>[]`

Define custom SWC transformation rules for specific files.

```ts
export default defineConfig({
  transform: {
    swc: {
      rules: [
        {
          filter: { id: /\.custom\.ts$/ },
          options: {
            jsc: {
              parser: {
                syntax: 'typescript',
              },
            },
          },
        },
      ],
    },
  },
});
```

**SwcTransformRule:**

```ts
interface SwcTransformRule {
  filter?: HookFilter | TopLevelFilterExpression[];
  options: swc.Options | ((code: string, id: string) => swc.Options);
  standalone?: boolean;
}
```

With `standalone: false` (the default), options from matching rules are merged, and SWC parses and transforms each matching module once.

With `standalone: true`, rules run separately, in declaration order, before the merged rules. Code-based filters and options callbacks receive the output of preceding transforms.

<Callout type="warn">

Each standalone SWC rule adds a separate parse and transform pass. Use a narrow `filter` to limit the cost.

</Callout>

## prelude

- **Type:** `string[]`
- **Default:** `react-native/setup-env` when available, with `react-native/Libraries/Core/InitializeCore` as a fallback

Modules imported before the app entry. Configured entries are appended to the defaults, with duplicates removed.

```ts
export default defineConfig({
  prelude: ['./src/setup.js'],
});
```

## polyfills

- **Type:** `(string | { type: 'plain' | 'iife'; code: string; withTransform?: boolean } | { type: 'plain' | 'iife'; path: string; withTransform?: boolean })[]`
- **Default:** React Native polyfills from `@react-native/js-polyfills`, with `react-native/rn-get-polyfills` as a fallback

Polyfills run before app modules.

String entries are loaded as raw source from files. Object entries can provide inline `code` or a file `path`. Relative file paths resolve from the process working directory. Set `withTransform: true` on an object to transform the polyfill; the default is `false`.
Use `type: 'iife'` when the polyfill should run in its own function scope, or `type: 'plain'`
to run it as-is.

```ts
export default defineConfig({
  polyfills: [
    {
      type: 'iife',
      code: 'globalThis.window = globalThis;',
    },
  ],
});
```

## output

Output configuration.

<Callout>
  `output` extends Rolldown's `OutputOptions`, except `file`, `dir`, `format`, `codeSplitting`, and
  `persistentCache`, which Rollipop manages automatically.
</Callout>

Other Rolldown output options such as `banner`, `footer`, `intro`, `outro`, `sourcemap`, and
`minify` are also configured under `output`.

## dev

Development mode configuration.

### dev.watch

File watcher configuration for development mode.

<Callout>
  `dev.watch` accepts Rolldown's `DevWatchOptions`. The defaults below are set by Rollipop.
</Callout>

#### dev.watch.skipWrite

- **Type:** `boolean`
- **Default:** `true`

Skip writing output files during watch mode.

#### dev.watch.useDebounce

- **Type:** `boolean`
- **Default:** `true`

Use debouncing for file change events.

#### dev.watch.debounceDuration

- **Type:** `number`
- **Default:** `50`

Debounce duration in milliseconds.

#### Other Watch Options

| Option                      | Type                                       | Default               | Description                                                                             |
| --------------------------- | ------------------------------------------ | --------------------- | --------------------------------------------------------------------------------------- |
| `enabled`                   | `boolean`                                  | `true`                | Enable file watching and automatic rebuilds.                                            |
| `usePolling`                | `boolean`                                  | `false`               | Poll instead of using native file-system events.                                        |
| `pollInterval`              | `number`                                   | `100`                 | Polling interval in milliseconds.                                                       |
| `compareContentsForPolling` | `boolean`                                  | `false`               | Compare contents when polling.                                                          |
| `debounceTickRate`          | `number`                                   | automatic             | Debouncer tick interval in milliseconds; defaults to one quarter of `debounceDuration`. |
| `include`                   | `string \| RegExp \| (string \| RegExp)[]` | `[]`                  | Limit which discovered files are watched. Strings are globs.                            |
| `exclude`                   | `string \| RegExp \| (string \| RegExp)[]` | `['**/.rollipop/**']` | Exclude discovered files from watching. Strings are globs.                              |

These options belong under `dev.watch`.

### dev.hmr

- **Type:** `boolean | HmrConfig`
- **Default:** `true`

Enable or configure Hot Module Replacement (HMR). HMR is available only when `mode` is `development`.

```ts
export default defineConfig({
  dev: {
    hmr: true,
  },
});
```

**Advanced HMR Configuration:**

The implementation fields accept source code, so read custom implementation files before passing them:

```ts
import { readFileSync } from 'node:fs';
import { defineConfig } from 'rollipop';

export default defineConfig({
  dev: {
    hmr: {
      runtimeImplement: readFileSync(new URL('./custom-hmr-runtime.js', import.meta.url), 'utf8'),
      clientImplement: readFileSync(new URL('./custom-hmr-client.js', import.meta.url), 'utf8'),
    },
  },
});
```

**HmrConfig:**

```ts
interface HmrConfig {
  runtimeImplement?: string; // Custom HMR runtime source
  clientImplement?: string; // Custom HMR client source
}
```

## reactNative

React Native specific configuration.

### reactNative.reactNativePath

- **Type:** `string`
- **Default:** value of the `ROLLIPOP_REACT_NATIVE_PATH` environment variable if set, otherwise the resolved `react-native` package path from the project root

Path to the React Native package. An explicit value overrides the environment variable and package resolution.

```ts
export default defineConfig({
  reactNative: {
    reactNativePath: '/path/to/custom/react-native',
  },
});
```

### reactNative.assetRegistryPath

- **Type:** `string | ((root: string) => string | Promise<string>)`
- **Default:** `'react-native/asset-registry'` when available, with `'react-native/Libraries/Image/AssetRegistry.js'` as a fallback

Path to the asset registry module. Resolved relative to the project root. May also be a (possibly async) function that receives the project root and returns the path.

```ts
export default defineConfig({
  reactNative: {
    assetRegistryPath: (root) => path.resolve(root, 'src/asset-registry.js'),
  },
});
```

### reactNative.hmrClientPath

- **Type:** `string | ((root: string) => string | Promise<string>)`
- **Default:** `'react-native/Libraries/Utilities/HMRClient.js'`

Path to the HMR client module used at runtime. Resolved the same way as `assetRegistryPath`. Override this when shipping a custom HMR client (e.g. for older React Native versions — see the `examples/0.72` setup for a real-world case).

## plugins

- **Type:** `PluginOption`

Rollipop plugins, including arrays, promises, and conditional entries such as `false` or `undefined`. See [Plugin API](/docs/apis/plugin) for more details.

```ts
import myPlugin from 'rollipop-plugin-example';

export default defineConfig({
  plugins: [myPlugin()],
});
```

## commands

- **Type:** `InteractiveCommand[]`

Add custom interactive commands to the development server's interactive mode.

```ts
export default defineConfig({
  commands: [
    {
      key: 'c',
      description: 'Clear console',
      handler() {
        console.clear();
      },
    },
  ],

```

**InteractiveCommand:**


## reporter

- **Type:** `Reporter`
- **Default:** `ClientLogReporter`

Custom reporter for build events. Implement the `Reporter` interface to create custom reporters. A configured reporter is combined with the default reporter.

See [Reporter](/docs/features/reporter) for more details.

## analyzer

- **Type:** `AnalyzerConfig`
- **Default:** `{ enabled: false, analyzeFile: 'analyze-data.json', reportFile: 'report.html', autoOpen: false }`

Generate bundle analysis data and an HTML report. See [Bundle Analysis](/docs/features/analyze) for all four options and output paths.

## envDir

- **Type:** `string`
- **Default:** the `cwd` passed to `loadConfig` (`process.cwd()` by default)

Directory to load environment files from. Setting `root` alone does not change this default; set `envDir` explicitly when using a different environment directory.

```ts
export default defineConfig({
  envDir: './envFiles',
});
```

## envFile

- **Type:** `string`
- **Default:** `'.env'`

Base name for environment files loaded from [`envDir`](#envdir).

The loader checks `${envFile}`, `${envFile}.local`, `${envFile}.[mode]`, and `${envFile}.[mode].local`. Use a file name, not a path.

```ts
export default defineConfig({
  envFile: '.rollipop-env',
});
```

## envPrefix

- **Type:** `string`
- **Default:** `'ROLLIPOP_'`

Prefix for environment variables to be included in the bundle.

```ts
export default defineConfig({
  envPrefix: 'MY_APP_',
});
```

## treeshake

- **Type:** `boolean | rolldown.TreeshakingOptions`
- **Default:** `true`

Enable or configure tree-shaking for standalone bundles. The development server disables tree-shaking for development bundles.

## optimization

Rolldown optimization configuration. Rollipop forces `inlineConst: false` for its module format; use `rolldownOptions` only if you need to override the final generated settings.

## output.minify

- **Type:** `boolean | 'dce-only' | MinifyOptions`
- **Default:** `false`

Control code minification.

- `true`: Enable full minification including code compression and dead code elimination
- `false`: Disable minification
- `'dce-only'`: Only perform dead code elimination without code compression
- `MinifyOptions`: Fine-grained control over minification settings

```ts
export default defineConfig({
  output: {
    minify: true,
  },
});
```

## experimental.lazyBarrel

- **Type:** `boolean`
- **Default:** `false`

Skip unused re-exports in side-effect-free barrel modules to reduce build time.

See [Lazy Barrel Documentation](https://rolldown.rs/in-depth/lazy-barrel-optimization) for details.

## output.sourcemap

- **Type:** `boolean | 'inline' | 'hidden'`
- **Default:** `true` for the development server, `false` for standalone bundles

Whether to generate sourcemaps. The CLI's `--sourcemap-output` option enables sourcemaps for a bundle and selects the output file path.

- `false`: No sourcemap will be generated
- `true`: A separate sourcemap file will be generated
- `'inline'`: The sourcemap will be appended to the output as a data URL
- `'hidden'`: A separate sourcemap file will be generated, but the sourcemap URL comment will not be included in the output

```ts
export default defineConfig({
  output: {
    sourcemap: true,
  },
});
```

### output.sourcemapBaseUrl

- **Type:** `string`

Base URL for links to sourcemap files. When set, absolute URLs will be generated instead of relative ones. Useful when deploying sourcemaps to a separate location like a CDN.

### output.sourcemapDebugIds

- **Type:** `boolean`
- **Default:** `false`

Include [debug IDs](https://github.com/tc39/ecma426/blob/main/proposals/debug-id.md) in the sourcemap. A unique debug ID helps identify sourcemaps across different builds.

### output.sourcemapIgnoreList

- **Type:** `boolean | string | RegExp | ((source: string, sourcemapPath: string) => boolean)`
- **Default:** `/node_modules/`

Control which source files are included in the sourcemap ignore list. Files in the ignore list are excluded from debugger stepping and error stack traces.

<Callout type="info">
  Using static values (`boolean`, `string`, or `RegExp`) is significantly more performant than
  functions. Prefer static patterns when possible.
</Callout>

### output.sourcemapPathTransform

- **Type:** `(source: string, sourcemapPath: string) => string`

Transform each path in a sourcemap. By default, Rollipop rewrites source paths relative to the project root.

```ts
export default defineConfig({
  output: {
    sourcemapPathTransform: (source) => {
      return source.replace(/^src\//, '');
    },
  },
});
```

## tsconfig

- **Type:** `boolean | string`
- **Default:** `true`

Use `true` for automatic resolution, `false` to disable it, or a string for an explicit `tsconfig.json` path. See [TypeScript](/docs/get-started/typescript) for client types and type checking.

## external

- **Type:** `string | RegExp | (string | RegExp)[] | ((source: string, importer: string | undefined, isResolved: boolean) => boolean | null | undefined)`

Exclude modules from the bundle. The runtime must provide them, or the application must handle their absence.

```ts
export default defineConfig({
  external: ['optional-native-integration'],
});
```

## runtimeTarget

- **Type:** `'hermes' | 'hermes-v1'`
- **Default:** `'hermes-v1'`

Target JavaScript engine. Use `'hermes'` for Hermes versions before Hermes V1.

## experimental

Accepts Rolldown's experimental options and Rollipop's [`worklets`](/docs/experimental/reanimated-worklets) transform. These options may change without a major version bump.

## rolldownOptions

- **Type:** `RolldownOptions | ((config: RolldownOptions, context: RolldownOptionsContext) => RolldownOptions | Promise<RolldownOptions>)`

Override Rollipop's final generated Rolldown configuration.

Object values are merged after Rollipop's generated options. Function values receive the final
generated options and can return a replacement. The second argument contains resolved build options plus `id`, `root`, and `buildType` (`'build'` or `'serve'`):

```ts
export default defineConfig({
  rolldownOptions: (options, { platform, buildType }) => ({
    ...options,
    output: {
      ...options.output,
      banner: `/* ${platform}: ${buildType} */`,
    },
  }),
});
```

<Callout type="warn">
  Overrides can replace Rollipop's required bundler settings and break the build.
</Callout>

```ts
export default defineConfig({
  rolldownOptions: {
    input: {
      external: ['react'],
    },
    output: {
      banner: '/* generated */',
    },
  },
});
```

```ts
export default defineConfig({
  rolldownOptions: (config) => {
    return {
      ...config,
      input: {
        ...config.input,
        // Custom Rolldown input options
      },
    };
  },
});
```
